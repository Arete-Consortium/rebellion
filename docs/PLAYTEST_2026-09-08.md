# September 8 playtest: save recovery and combat audio

This follow-up continues the free portfolio/community game's Mac candidate while physical controller troubleshooting is handled separately. The [September 7 checkpoint](MAC_PLAYTEST_REPORT.md) records the chapter flow, hull import, commander repairs and earlier build evidence.

## Changes

- Native saves write and sync a temporary file beside `save.json`, then rename it into place. A changed valid primary is retained as `save.json.bak` before replacement. Loading tries that backup when the primary is missing or cannot be read/parsed. Loading itself does not alter either file.
- Before autosave replaces invalid primary contents, those exact bytes are preserved in a unique `save.corrupt-*.json`. If reading or preserving existing data fails, that save transaction stops. A failed backup replacement leaves the primary intact. The JSON schema and `REBELLION_HOME` location remain compatible with existing saves.
- Shield, armor and hull impacts have distinct synthesized resonance, metallic ring and structural crunch. Health warnings use distinct pulse patterns with faded edges. Critical hull danger interrupts an earlier, less urgent warning; the system avoids repeating alarms while health stays low and uses a recovery threshold to prevent shield-regeneration chatter.
- Explosion playback permits eight ordinary voices, at most three new ordinary voices per frame, and reserves one voice for a boss explosion. Excess ordinary events are consumed rather than delayed into a sound backlog. This complements the existing weapon-voice cap; it is not a master-bus limiter.
- Music now follows `BossFight` for both chapters and stops the combat loop with one sting on mission results. The music and master sliders also update the existing menu track while Options is open. The game uses its generated music throughout. Removed unused Ogg override handles and automatic requests for five files that are not shipped; no new audio dependencies were added.

## Qualification boundaries

Disk regressions use isolated temporary saves. They cover populated saves, corrupt/missing primary recovery, preserved damaged bytes, failed backup replacement and temporary-file cleanup. They do not simulate every power-loss/filesystem failure, merge progress from concurrent game instances or qualify Windows. Browser localStorage behavior is unchanged. Recovery/write diagnostics currently appear in logs; a player-facing recovery notice remains future UX work.

Audio regressions verify warning priority, duplicate suppression, explosion budgeting, result transitions and generated cue edges/levels. They do not establish the final perceived mix. Listen during normal and crowded combat on speakers and headphones; ability, pickup and menu cues still need the next polish pass.
